# Patching notes
This client is similar enough to the 2018 (13n60) one that I was able to copy over most of the code. I also used the exact same event-and-hook model, and the clients function identically in most aspects. See [here](https://github.com/Celarious/OpenShores-2018-ClientMod/blob/main/docs/notes.md) for 2018 client notes which the majority of this work is based on.

#### States
Despite the similarities, this client had _some_ logical differences from the 2018 one. Importantly, the login field creation isn't split off into its own sub-function in this client, so I had to combine both the scrolling text modification and the IP input field insertion into state 5. This also means the states after had to be shifted down one.
In addition, the way the login fields are positioned on the login screen is completely different, and much harder to work with. As a result, the state 5 code is a lot more complex than the equivalent 2018 version. Specifically, the controls are organized into a `QGridLayout`, with rows determining their vertical position. The first two rows are spacers, meaning adding the IP input field there moves the whole login box up a lot. Because of this, I instead created a QVBoxLayout sub-layout containing both our new IP input field and the existing username field, and assigned that to row 3, where the username field previously was.

#### Other
The main issue with this client that took days to solve was ALL input field (QLineEdit) backgrounds in the game flashing white on hover. The 2018 client didn't do this, so it was very difficult to find the cause.
The issue didn't happen on Windows 7, meaning some regression in Windows 8/10 causes it. After spending way too long digging, I found that the issue appeared to be with Windows 10's Uxtheme.dll and the sprites it returns, interacting badly with Qt 5.5.1's state-swap code, possibly also related to alpha blending. NOPing the faulty DrawThemeBackgroundEx call and other related calls fixed the background flashing but the white border vanished on idle, and faded in and out inconsistently on hover on other non-login interfaces such as in the Settings -> Comm input fields, meaning this wasn't a suitable fix.
Because patching Uxtheme.dll is not feasible, we instead replaced the faulting QProxyStyle::drawPrimitive() call in AuGlobal13.dll with our own custom exported function that takes the previously done rectangle border calculation, and draws an RGB255,255,255 (white) rectangle using `QPainter->drawRect()` at a width of 1.
